# CAMPUS_DECISIONS_NEEDED — 결정이 필요한 항목

버전 1.0 · 브랜치 `feat/campus-territory-prototype`

각 항목은 **현재 구현이 어떻게 가정했는지**와 **바꾸려면 무엇을 고쳐야 하는지**를 함께 적었습니다.
전부 프로토타입 기본값이며, 확정되면 상수/RPC 한 곳만 고치면 됩니다.

---

## D-1. 친구 세션 완주 점수의 성격 — **가정으로 진행**

요청서에는 `정상 완료 세션 +100` 과 `친구 세션 완주 +50` 이 나란히 있습니다.
두 해석이 가능합니다.

| 해석 | 결과 |
| --- | --- |
| **A (현재 구현)** 친구 완주는 **추가 보너스** | 친구 방 세션 완주 = 100 + 50 = **150** |
| B 친구 완주가 완료를 **대체** | 친구 방 세션 완주 = 50 |

현재는 A 입니다. 서로 다른 `kind` 로 각각 세션당 1회 기록됩니다.
B 로 바꾸려면 `CampusContributionBridge` 에서 `mode === 'room'` 일 때
`session_completed` 를 보내지 않도록 한 줄만 조건을 바꿉니다.

---

## D-2. 하루 최대 기여도 값 — **600점으로 가정**

- 근거: 25분 세션 4회(400) + 회복 5회(100) + 스트레칭 5회(100) ≈ 하루 상한선.
- 상한에 걸리면 **남은 만큼만** 인정하는 부분 적립입니다. (전면 거절 아님)
- 바꿀 곳: `CONTRIBUTION_LIMITS.dailyCap` + SQL `campus_record_contribution` 의 `600`.

같이 정할 것: 상한 기준 시각.
현재 클라이언트는 **브라우저 로컬 날짜**, 서버는 **Asia/Seoul** 입니다.
해외 사용자가 있으면 한쪽으로 통일해야 합니다.

---

## D-3. 시즌 길이와 시즌 경계 — **14일, 코드 계산으로 가정**

- 현재: 14일 고정, 기준 시각 `2026-01-05 UTC` 에서 시즌 번호를 계산합니다.
  서버 없이도 "남은 시간"과 "종료 → 초기화"를 확인할 수 있게 한 프로토타입 장치입니다.
- Supabase 를 붙이면 `campus_seasons` 행이 기준이 되고, 시즌 생성·보관은
  `campus_seed_season` / `campus_archive_season` 배치가 담당합니다.
- 정할 것: 실제 시즌 길이(2주/4주/학기 단위), 시작 시각(월요일 09:00 KST 등),
  시즌 사이 공백 여부.

---

## D-4. 학교 변경 제한의 조합 — **AND 로 가정**

요청서: `시즌 중 1회 또는 7일에 1회`.

- 현재 구현은 **둘 다 만족해야** 변경 가능(AND)입니다.
  → 다음 변경 가능 시점 = `max(시즌 종료, 마지막 변경 + 7일)`
- OR(둘 중 하나만 만족) 로 하면 훨씬 느슨해집니다.
- **첫 선택은 변경으로 세지 않습니다.** (처음 고른 뒤 한 번은 바로 바꿀 수 있음)
  이것도 확정이 필요합니다 — "첫 선택도 즉시 잠금" 으로 바꿀 수 있습니다.
- 바꿀 곳: `features/campus/schoolChange.ts` + SQL `campus_set_school`.

---

## D-5. 기여 대상 타일을 사용자가 고르게 할지 — **고르게 함(현재)**

- 현재: `/campus/map` 에서 타일을 골라 `기여 대상으로 설정` 할 수 있고,
  고르지 않으면 ① 내가 공격 중인 타일 중 진행도 최고 ② 가장 약한 남/중립 타일 순으로 자동 배정.
- 대안: 전부 자동 배정(전략 요소 제거) / 학교 내 투표로 결정(구현 비용 큼).

## D-6. 640px 미만 레이아웃 — **범위 밖으로 남겨 둠**

- `AppShell` 이 232px 고정 사이드바를 쓰기 때문에 **캠퍼스 이전부터**
  390px 폭에서 가로 스크롤이 있습니다. (`/` 396px, `/room/new` 437px)
- 요구사항인 1280 × 800 / 1440 × 1000 은 통과하며, 1024 · 768 도 통과합니다.
- 모바일을 지원하려면 사이드바를 `lg` 이상에서만 보이게 하고 하단 탭바를 넣는
  **앱 전역 변경**이 필요합니다. 캠퍼스 프로토타입 범위를 넘어서므로 손대지 않았습니다.

---

## D-7. mock 저장소의 탭 간 동시 쓰기 — **Web Locks 로 직렬화 (해결)**

- 기여 반영의 `read-modify-write` 전체를 `navigator.locks.request` 로 감싸고,
  상태를 localStorage 에서 다시 읽어 적용합니다.
  → 다른 탭의 갱신을 덮어쓰지 않습니다. (테스트로 고정)
- Web Locks 미지원 브라우저에서는 잠금 없이 진행하므로 아주 좁은 경합 창이 남습니다.
  Supabase 경로는 `FOR UPDATE` 행 잠금이라 애초에 유실이 없습니다.
- 남은 결정: mock 을 완전 엄격하게 만들 필요가 있는지(프로토타입에는 과합니다).

---

## D-8. 학교 색 프리셋의 최종 승인 — **디자인/법무 확인 필요**

- 지금 색은 **이 프로토타입이 임의로 고른 값**이며 화면에도 그렇게 표시합니다.
- 공식 색을 쓰려면 각 학교의 브랜드 가이드 확인·사용 허락이 필요합니다.
- 학교 이름 텍스트 사용 자체도 확인이 필요할 수 있습니다.
  (공식 로고·마스코트는 사용하지 않았습니다)

---

## D-9. 대학 인증 도입 여부 — **미도입**

- 지금은 사용자가 직접 고르고, 화면 곳곳에 "비공식" 을 표시합니다.
- 인증(학교 이메일 등)을 넣으면:
  - 학교 변경 제한의 의미가 커집니다.
  - 개인정보 처리 범위가 늘어납니다 (이메일 도메인 보관 여부).
  - "공식" 표현을 쓸 수 있는지는 여전히 학교와의 협의 사항입니다.

---

## D-10. 시즌 종료 시 보관 범위 — **최종 지도 + 학교별 기여도로 가정**

- mock 은 종료 시즌의 타일 96칸과 학교별 집계를 보관합니다 (최근 8시즌).
- Supabase 경로도 보관 시즌의 **최종 지도와 학교별 기여도까지** 불러옵니다.
  최근 **3시즌**까지만 상세를 가져오고, 보관 시즌은 더 변하지 않으므로 캐시합니다
  (Realtime 갱신마다 지난 시즌 타일을 다시 조회하지 않습니다).
- 정할 것: 상세를 보여 줄 시즌 수(현재 3), 보관 기간, 개별 사용자 기여 이력 보관 기간.

---

## D-11. 시즌 남은 시간 실시간 갱신 — **미구현(P2)**

- 현재 `Date.now()` 를 렌더 시점에 읽습니다. 화면을 열어 둔 채로 두면
  남은 시간이 자동으로 줄지 않습니다 (표시는 분 단위).
- 필요하면 1분 간격 타이머를 `useCampusScreen` 에 넣으면 됩니다.

---

## D-12. QA 주입 경로의 기여 허용 — **E2E 전용으로 열어 둠**

- `window.__uprightCampus` 는 `VITE_ENABLE_QA_LAB` + `VITE_ENABLE_CAMPUS_TERRITORY`
  가 모두 켜진 빌드에서만 설치되며, 데모 가드를 통과해 기여를 만들 수 있습니다.
  두 탭 동기화·중복 차단을 브라우저에서 검증하기 위한 장치입니다.
- Production 빌드는 `VITE_ENABLE_QA_LAB=false` 이므로 설치되지 않습니다.
- 사용자 화면에서 들어오는 QA(= `/lab`, `?demo=1`)는 데모 모드가 켜지므로 기여도가 없습니다.
